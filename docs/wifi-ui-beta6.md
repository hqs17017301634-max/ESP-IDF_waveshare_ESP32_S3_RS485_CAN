# WiFi 扫描、系统状态和已保存网络修复

版本：`3.0.0-beta.6`。基线为 `883e0ad`，保留单路 CAN Coordinator 和现有 WiFi/NVS 数据结构。

## 复现与修复

| 问题 | 已复现的原因 | 修复 |
|---|---|---|
| 扫描显示没有网络 | CAN 优先模式要求手动参数，按钮却访问普通 `/wifi_scan`；加参数后旧固件实际可扫描到 17 个热点 | 按钮请求 `/wifi_scan?force=1`，区分错误和空结果；手动扫描 5 秒内复用缓存 |
| 系统状态大片空白 | 优先模式只返回 `priorityMode` 一个字段；监测关闭还会清空界面 | 优先模式返回完整缓存快照，最多每 10 秒采样；页面先加载一次，暂停保留最近数据 |
| 已连接但显示“未保存网络、0/4” | 默认网络性能模式未加载/刷新已保存列表，模块 API 实际返回 2 条 | 初始化、页面恢复可见、状态变化和 30 秒刷新均读取小型保存列表；加载失败不再表示没有保存 |

底层扫描返回负值和具体错误名，避免把连接忙或驱动失败当作没有热点。扫描结果内存最多保存 40 条，页面最多展示 20 条。
CPU 负载计算使用 64 位中间值防止长采样间隔乘法溢出；开机先建立 CPU 采样基线。
任务状态也使用缓存，前端监测周期降低到系统 5–10 秒、任务 15 秒。
连接提示仅显示连接状态和上游 IP，不再要求用户离开模块管理热点。

## 验证结果

- `test/test_wifi_system_ui.js`：12 个场景通过，包括手动扫描 URL、失败/超时、按钮恢复、缓存、完整状态、首次快照、保存列表和性能模式刷新。
- Python 回归：23 项通过。
- 构建环境：`waveshare_ESP32_S3_RS485_CAN`，ESP-IDF 6.0.1，ESP32-S3、16 MB DIO。
- 已通过当前模块 `/update` 完成 OTA，响应 `200 OK`；重启后读到版本 `3.0.0-beta.6`，运行于 app1 / `0x420000`。
- 两条已保存 WiFi 的内容和槽位元数据与更新前一致。
- CAN 优先模式开启时：系统接口返回 59 个字段，CPU 240 MHz、CPU 负载有效、PSRAM 8 MB、Flash 16 MB；任务接口有 14 行。
- API 扫描发现 18 个热点，紧接的第二次请求返回缓存；浏览器按钮实测发现 17 个热点。两次扫描时间不同，数量随环境变化。
- 浏览器显示 `(2/4)` 和两个已保存条目；系统面板显示完整数据，暂停监测后数据仍保留。
- CAN 写入开关始终关闭，验证后 CAN 优先模式恢复为更新前的关闭状态。

本次是模块 OTA、WiFi 管理页面和扫描的实机验证，不构成车辆 CAN 效果、不同手机型号的中继吞吐或长时间稳定性验证。
此前审查发现的 NAT 线程封装、WPA3 参数、DNS 大响应等问题没有在这次界面修复中一并修改。
