# S3 beta.8：FSD 优先调度与无密码 OTA

适用目标：`waveshare_ESP32_S3_RS485_CAN`，ESP32-S3，ESP-IDF 6.0.1，
TX GPIO15 / RX GPIO16，500 kbit/s，16 MiB Flash。
父提交为 `b6f3a7e`；沿用单路 CAN、逐 RX 字段合成架构。

## 最终调度规则

业务模块仍只贡献字段意图。同一份 RX 最多 finalize 一次、生成一个最终请求。
优先级赋给整份合成结果，原 CAN ID、MUX、车型字段布局保持不变。

| 等级 | 内容 |
|---|---|
| 最高 | Legacy `0x3EE MUX0`、HW3/HW4 `0x3FD MUX0` 中包含 FSD 意图的结果；HW4 当前启用的 MUX1 Ready 修改 |
| 普通 | HW3 MUX2 速度、HW4 MUX2 Profile、Legacy MPP 等其他已有业务请求 |

HW3/Legacy 同一 MUX0 的驾驶风格和 FSD 合在一起，整帧优先发送。
不同 MUX 不合并、不等待收齐；同一级保持源序号顺序。
调度器不会为了最高优先级额外启用未开放功能。

FSD 优先调度始终应用于已有业务请求。页面上的 CAN 优先模式继续控制
接收过滤和部分诊断刷新策略；关闭该模式不会把发送调度改回普通 FIFO。

## FIFO 与时间边界

| 项目 | beta.8 配置 | 说明 |
|---|---:|---|
| TWAI RX 软件队列 | 64 帧 | 保留现值；本轮没有实车 RX 溢出证据支持扩容 |
| Broker 待发槽位 | 16 帧 | 最高级 8、普通级 8，固定容量，无热路径动态分配 |
| TWAI 驱动 TX 软件队列 | 0 | 关闭驱动排队；硬件仍可持有一份已接受请求 |
| 单请求最大尝试次数 | 8 次 | Busy 后最早隔 1 ms 再试，包含首次尝试 |
| 软件出队年龄上限 | 20 ms | 暂定保护值，必须继续通过总线负载测试评估 |

控制器出现发送机会时，Broker 先选最高级，随后才选普通级。已经接受的
普通请求不能被后来到达的 FSD 抢占；但不会有 16 份普通请求积压在驱动 FIFO 前面。
最高级持续积压时，普通请求可能因过期被丢弃，诊断中会记录原因。

20 ms 从软件出队时刻开始计，不包括原始 RX 在硬件/驱动队列中的等待。
它限制软件提交年龄，不是物理接收至实际发送完成的硬截止时间。
控制器仲裁、自动重传及总线拥塞仍可能延长已经接受请求的实际发送时间。
CAN 总线仲裁优先级仍由原 CAN ID 决定。

## 请求生命周期与配置边界

- Broker 自有槽位保存最终帧及元数据，不保存局部 `TxRequest` 地址。
- 在入口按源序号去重，在队列中逐请求维护消费状态；允许较新的 FSD
  先发送后，较早的普通请求仍正常发送，不再按“最大已发送序号”误删。
- Busy 只表示未接受。重试使用同一帧和原截止时间，不重算业务逻辑、不推进速度平滑。
- 驱动接受后才更新速度的已入队值与时间；接受不等同 TX-done、ACK 或 ECU 接受。
- 配置修改与 CAN 帧事务使用同一运行时锁。待处理配置会让 CAN 任务让出执行机会；
  完整变更结束后才恢复事务，避免一帧混用不同配置。
- 请求记录配置/控制器代次。配置切换、控制器恢复、OTA、休眠会使旧请求失效。
- 提交前重新检查现有的主开关、休眠和 Legacy/HW3 FSD AP 门控。
- 配置修改、OTA 和休眠交接先取消尚未提交请求，对已接受请求有界等待最多
  20 ms，然后停止控制器。仍有未确认请求时计入 `quiesce_unknown`。
  配置修改期间 CAN 会有暂停窗口；HTTP 回包前释放运行时锁。
- OTA 成功后保持静默直到重启；OTA 拒绝、开始/结束失败或中止时恢复运行。

## 接收过滤

优先白名单按当前功能依赖补齐：AP 门控保留所需 `0x118/0x186/0x399/0x3F8`，
自动休眠保留 `0x118/0x273/0x339`，且仅加入当前车型处理器支持的 ID。
过滤集合相同（包括不同排列顺序）时不重建驱动。配置交接中的停止/恢复
与过滤集合变化导致的卸载/重建是两个独立动作。

优先模式未保留 `0x7FF` 时，返回 `gtw_status_filtered=true`，GTW 状态不再显示缓存旧值。

## OTA 密码

按用户要求取消 OTA 用户名、密码提示和 Authorization 参数，移除凭据重置按钮，
清理旧浏览器凭据缓存，不再要求构建配置提供 `DASH_OTA_USER/PASS`。
保留 ESP-IDF 镜像格式、分区大小和 OTA 完整性检查。
原 IDF 兼容层的 `authenticate()` 实际一直返回 true；本次把前端和 OTA 调用入口统一为无密码。

## 验证结果

- Native：14 个套件、210 项测试通过，其中 13 项调度/过滤测试，5 项直接编译
  生产 TWAI 驱动并替换 ESP-IDF 后端的接口测试。
- Python：24 项通过，包含直接提取生产 `UpdateClass` 编译运行的 OTA 生命周期测试。
- WebUI：12 个原有场景通过；新增 XHR 测试确认无提示、无凭据存储读取、无认证头。
- CAN 差分：3 个配置组合共 688,128 次 RX，与基线输出一致（驱动立即可接受的条件）。
  拥塞下的优先顺序、过期丢弃由新增测试独立覆盖。
- S3 隔离构建、镜像信息、校验和与分区检查通过。
- 无凭据 OTA 实际返回 HTTP 200 `OK`，模块重启后确认 `3.0.0-beta.8`，
  从原 app1 切换到 app0；设备身份一致。
- Windows 在重启时切回原 WiFi，随后显式选择 `EVtools` 配置与 SSID 后重连。
  没有重复上传固件。
- 两个已保存网络保留；升级前 CAN 写入和优先模式均为 true，上传前临时关闭
  写入，验证后恢复 true。系统返回 59 个字段，中继 NAT 为 ready。
- 运行模块网页已确认不含密码提示，使用无凭据上传调用。
- 设备调度状态：`fsd_first`，容量 16、最高级预留 8、驱动 TX 队列 0、RX 队列 64，
  恢复后 `paused=false`；采样时待发和错误计数为 0。

本轮模块 RX/TX 均为 0，没有真实 CAN 总线负载、TX 完成/ACK、车辆激活效果或
长期压力测试证据。当前 FIFO、重试和时间参数属于已通过软件验证的初始配置。

- OTA：`s3-fsd-priority-beta8_OTA.bin`，1,139,216 字节。

- 全量：`s3-fsd-priority-beta8_FULL_16MB.bin`，16,777,216 字节，从 `0x0` 线刷。
